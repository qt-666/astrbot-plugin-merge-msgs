# astrbot-plugin-merge-msgs

给 AstrBot 用的「连续消息合并」插件：等用户把话说完，再统一回复一次。

## 它解决什么

群聊里常见这种情况：

```
用户：我这
用户：一段话
用户：分好几句
```

默认情况下，AstrBot 会把每条都当成一次独立提问，于是它回三次，还会答得驴唇不对马嘴。

这个插件会在**本地**等几秒：只要用户还在继续发，就继续等；一旦安静超过 4 秒，就把这几条拼成一句交给模型，只回一次。

## 效果

```
用户：我这 / 一段话 / 分好几句 / 你等我说完
模型收到：我这，一段话，分好几句，你等我说完
```

## 安装

把整个目录放到 AstrBot 的插件目录：

```
<AstrBot>/data/plugins/astrbot_plugin_merge_msgs/
```

然后重启 AstrBot，或到 WebUI 插件页重载。

## 配置

没有面板配置，参数写在 `main.py` 顶部：

| 常量 | 默认 | 说明 |
|---|---|---|
| `IDLE_SECONDS` | 4.0 | 多久没新消息算“说完了” |
| `MAX_WAIT_SECONDS` | 25.0 | 单批最多等多久，防止一直等 |
| `TICK_SECONDS` | 0.3 | 检查间隔，一般不用改 |

打字慢的可以调到 5~6 秒；想更快收到回复就调到 2~3 秒。

## 行为细节

- **按消息 ID 排序**，并发到达也不会乱序
- 自动去掉 `@xxx(123456)` 前缀，避免合并文本里一堆 @
- 以 `/` 开头的命令**不参与合并**，保证指令正常执行
- 只影响“回复”，模型拿到的仍是普通文本

## 已知问题

- 每条消息都会**延迟约 4 秒**，对追求即时性的场景不友好
- 同一个会话里两个人同时说话，可能被分别合并，也可能互相干扰（按 key = 会话 + 发送者隔离，但没有做并发锁）
- 如果用户发完最后一条就离开，插件仍会等满 `IDLE_SECONDS`

## 兼容性

- AstrBot 4.x（在 4.29.1 上测试）
- 平台无关，任何能产生普通消息事件的适配器都能用（aiocqhttp 实测）
